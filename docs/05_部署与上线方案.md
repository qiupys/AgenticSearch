# 部署与上线方案

## 1. 服务形态

- **服务**：`serving/app.py`（FastAPI），`POST /predict`（单条）、`POST /batch`（≤50 条）、`GET /health`、`GET /metrics`
- **链路**：归一化 → LRU 缓存（命中率预期 15–25%）→ 三级级联意图 → NER → 槽位 → 召回翻译 → 统一 QP JSON
- **部署位置**：与业务服务同机共置（0.6B INT8 ~0.7GB 显存），或独立 QP 微服务

```bash
pip install -r requirements.txt
python -m serving.app            # 默认 0.0.0.0:8100
```

## 2. 模型加载与切换

| 组件 | 配置项（configs/service.yaml） | 行为 |
|---|---|---|
| Tier1 主模型 | `cascade.tier1_model.qwen_onnx_path` | 0.6B ONNX 就位后自动优先 |
| Tier1 备用 | `cascade.tier1_model.model_path` | 轻量模型（当前默认） |
| NER 模型 | `ner.model_weights_path` | 权重就位自动启用；否则词典规则兜底 |
| 门限 | `cascade.tier1_model.max_p_threshold` | 校准后 max-p ≥0.75 接受 |

## 3. 灰度与回滚

- **三路开关**：规则 / 模型 / 级联 各自独立开关 + 版本号，5%→25%→100% 灰度
- **秒级回滚**：模型版本开关切回规则快通道即可
- **灰度对比**：同 query 双跑（新旧 QP），记录意图差异率与召回 channel 差异率

## 4. 监控与告警

| 指标 | 告警条件 | 处置 |
|---|---|---|
| 分 Tier 流量占比 | Tier2 升级率跳升（>7% 或突增） | 分布漂移信号：先调门限/校准 |
| 门限通过率 | 持续下降 | 检查校准 ECE 是否漂移 |
| P50/P99 时延 | P99>50ms | 扩容 / 检查缓存命中率 |
| 线上 top1（回流量近似） | 环比异常 | 触发 badcase 分析 |
| 缓存命中率 | <10% | 检查归一化逻辑 |

## 5. Badcase 迭代闭环（考核阶段三要求）

```
线上 Query → 低置信/负反馈样本回流 → 原因分类（规则漏/模型错/体系缺/实体错）
   → 数据补充（hard negative 每混淆对 ≥200 条）→ 训练 → 离线评测（无退化校验）
   → 灰度上线验证 → 归档
```

- 频率：badcase 月度回流 + 混淆矩阵复盘；季度重训
- 体系修订：分布漂移（升级率持续偏高）触发意图体系聚类复查（对照 42 类）

## 6. 上线验收清单（对齐考核阶段三）

- [ ] 正式上线或达到发布标准（性能/稳定性/资源成本达标）
- [ ] 离线核心指标保持对 baseline 明显优势，主要场景无系统性退化
- [ ] 端到端 A/B：意图错误率下降 → 召回相关性/Top 结果质量正向
- [ ] 至少完成一轮基于线上问题的数据/模型迭代
- [ ] 技术文档、数据资产、评测体系、版本管理沉淀完整
