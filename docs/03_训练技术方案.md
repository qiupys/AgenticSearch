# 训练技术方案（0.6B 判别式三头 + NER 序列标注）

> 环境约定：训练在 GPU 服务器/集群进行；本机仓库只承载代码、数据与评测。
> 训练依赖见 `requirements-train.txt`（torch/transformers/onnxruntime）。

## 1. 意图识别：0.6B 判别式三头

### 1.1 能力边界认知

0.6B 中文金融语义弱：42 类细粒度裸指标上限约 L1 92–94% / L2 80–85%，生成式输出不可靠。
**设计原则：0.6B 只做级联中的一环（判别式编码器），系统级指标由「规则 + 校准门限 + 升级」三段拼接达成；teacher LLM 只在离线使用，在线零 LLM 依赖。**

### 1.2 模型结构

```
Qwen2.5-0.5B（编码器，最后一层池化向量 h）
   ├── L1 头：Linear(h→8)    CE 互斥，loss 权重 0.3
   ├── L2 头：Linear(h→42)   BCE 多标签，loss 权重 1.0
   └── 槽位头：Linear(h→k)   BCE 多标签，loss 权重 0.2（object_type/time_anchor/composite）
```

- 单次前向、无自回归解码、无 KV cache；单条 query 均长 ~35 token
- 解码：**软解码 score = p_L1(域) × p_L2(类)**，top-k 跨域；禁用 argmax 域内 mask（砍多意图且错误不可恢复）
- 升档：同架构直换 1.5B backbone，级联/代码全复用（INT8 ~1.1GB）

### 1.3 数据工程

| 环节 | 方案 |
|---|---|
| teacher 标注 | LLM 输出结构化 JSON（见 docs/02 第 5 节）；每条只调一次（温度 0 + 短 JSON + 前缀缓存 + 分级模型）；500 条人工验证集考 teacher ≥95% 再放量 |
| 造数规模 | teacher 2 万条 + 槽位重组增强 + 易混对定向造数 ≈ **3–4 万条**；复合样本 10–15% |
| 银标注 | 本仓库规则引擎已产出 10 万条（score≥2 高置信 5.3 万），作为弱监督预训练/扩充 |
| 难例挖掘 | 银标注 no_hit（1.1 万）+ 低分样本进难例池 → teacher 清洗 |
| 均衡 | 长尾类目（QUANT/SERVICE）过采样 + focal loss；头部降采样 |

### 1.4 训练策略

1. **软分布蒸馏**：1.5B/7B 中转学生或 teacher 软分布蒸馏（KL，T=2~4），42 类细粒度可再抬 3–5 点
2. **SupCon 监督对比**：8 对易混对（docs/02 第 3 节）定向对比学习——0.6B 表征弱时性价比最高
3. **多标签 BCE**：L2 头天然支持复合意图，规避域内 mask
4. **校准**：验证集温度缩放 + 按域分组校准，上线前 **ECE<0.05** 验收；门限 max-p≥0.75

### 1.5 导出与接入

- ONNX 导出（含 custom_metadata：l1_ids/l2_ids），INT8 PTQ（校准集精度损失 <0.5pt）
- 本仓库 `intent/qwen_head.py` 同接口加载；`configs/service.yaml` 填 `qwen_onnx_path` 即自动优先于轻量模型
- 验收指标：系统级 L1≥96% / L2≥88%（级联加权）；不达标处置顺序：查升级率→调门限→补 hard negative（每对 ≥200 条）→调蒸馏→升档 1.5B

## 2. NER：实体/时间识别（对标 99%）

### 2.1 任务与标签

7 类实体（BIO）：STOCK / STOCK_CODE / INDEX / FUND / INDUSTRY / MACRO / TIME。
标的（STOCK+STOCK_CODE）与 TIME 三类合并考核，对标业务目标 99%。

### 2.2 数据

- 弱标注：`scripts/export_ner_dataset.py` 已产出 20,000 条（train 19,600 / val 400），实体 34,741 个（TIME 15,627 / STOCK 7,438 / INDUSTRY 6,606 / STOCK_CODE 3,972 / MACRO 553 / FUND 289 / INDEX 256）
- 清洗：STOCK 后缀模式噪声最大，优先人工抽检 + 词典外实体链接（证券主数据）补召回
- 扩充：英文实体样本由海外 80 条基线 + 英文合成模板补齐（双语对齐要求）

### 2.3 模型与训练（服务器运行）

- **起点**：字符级 BiLSTM-CRF（char embedding + fastText 风格 3-gram 哈希 + BiLSTM + CRF），CPU/GPU 均可
- **目标版**：多语 BERT（bert-base-multilingual / xlm-roberta-base）+ CRF，对齐中英文统一要求
- 训练入口：`ner/train.py`（argparse：--data/--val/--epochs/--batch-size/--lr/--bert）
- 验收：实体级 F1 + 标的/时间口径 P/R/F1（目标 99%，规则+模型+实体链接级联达成）
- 导出：`data/models/ner_bilstm_crf.pt`（或 ONNX），`configs/service.yaml: ner.model_weights_path` 就位后线上自动切换模型推理，词典保留为低置信兜底

### 2.4 训练监控与资产管理

- 训练日志（loss/F1 per epoch）、checkpoint 保留 best-val、early stopping patience 3
- 模型版本管理：`data/models/` + 版本号命名；评测报告随模型版本归档
